Learning Outcomes

By the end of this tutorial, a learner will be able to:

  • Explain the separation of concerns between Electron’s main, preload, and renderer processes.
  • Configure a Vite-powered React renderer inside an Electron shell and run it in development mode.
  • Implement local persistence using the Web Storage API (`localStorage`) for a personal finance dashboard.
  • Extend a React single-page shell with sidebar navigation and multi-page state.
  • Evaluate trade-offs of Electron compared with native and PWA approaches, citing performance and distribution issues.
  • Build a executable desktop application for macOS, Windows, and Linux using electron-builder.

What You Build and Demo

You will run and understand Higgs, a desktop personal finance helper built with Electron and React. The app onboards a user, seeds starter data, lets you add income, expenses, investments, loans, and assets, and summarizes stats.

Scope of the demo

  • Desktop shell: Electron main process creates a BrowserWindow and wires preload.
  • Renderer: React (via Vite) renders onboarding, sidebar, and pages.
  • Data: `localStorage` persistence via `app/src/data/repo.js` with deterministic seeding (`seedData.js`).
  • Pages: Home, Income, Expenses, Investments, Loans, Assets (see `app/src/renderer/src/components/`).
  • Build: electron-builder targets macOS/Windows/Linux through npm scripts.

History and Standards

Electron originated at GitHub (2013, then “Atom Shell”) to bundle Chromium with Node.js so web engineers could deliver desktop apps. It follows core web standards (HTML5, CSS3, ECMAScript, DOM, Web Storage) and ships with a pinned Chromium to guarantee render consistency. Packaging standards leverage platform installers: dmg/zip (macOS), NSIS/zip (Windows), AppImage/Deb/RPM (Linux).

React (2013, Facebook) brought declarative UI with a virtual DOM. Vite (2020, Evan You) improved dev speed with native ES modules and fast HMR. Electron’s IPC and preload align with sandboxing principles to separate Node APIs from the browser context.

Key standards and specs

  • ECMAScript 2015+ (modules, promises), DOM Living Standard, CSS 2.1/3.
  • Web Storage API (localStorage) for persistence in the renderer.
  • CommonJS/ESM for module loading in main/preload (Node context).
  • Platform packaging: code signing and entitlements (macOS), MSI/NSIS (Windows), AppImage/Deb/RPM (Linux).

Architecture Overview

Processes and boundaries

  • Main process (`app/src/main/index.js`): creates BrowserWindow, loads renderer URL/bundle, controls lifecycle.
  • Preload (`app/src/preload/index.js`): safe bridge layer; keeps Node out of the renderer surface.
  • Renderer (`app/src/renderer/src/main.jsx`, `App.jsx`): React SPA hosting onboarding, sidebar, pages.

Data and state

  • Persistence: `app/src/data/repo.js` uses `localStorage` for `higgs:data` and `higgs:meta` keys.
  • Seeding: `app/src/data/seedData.js` builds starter categories and stats via `recalculateAllStats`.
  • Reset: `resetAll()` clears storage and returns to onboarding.

UI composition

  • App shell: `App.jsx` manages onboarding state, sidebar collapse, and page routing via local state.
  • Pages: components under `app/src/renderer/src/components/` (Home, IncomePage, ExpensePage, InvestmentPage, LoanPage, AssetPage, Sidebar, Versions).
  • Styling: `app/src/renderer/src/assets/*.css` plus inline styles for the welcome screen.

Code Snippets from the App

Onboarding and navigation (renderer shell)

// app/src/renderer/src/App.jsx
const meta = getMeta();
const [onboarded, setOnboarded] = useState(meta.onboarded);
const [name, setName] = useState("");
const [data, setData] = useState(load());
const [page, setPage] = useState("home");

function handleOnboard() {
  if (!name.trim()) return;
  const seeded = createSeedData(name.trim());
  save(seeded);
  setMeta({ onboarded: true });
  setData(seeded);
  setOnboarded(true);
}

Notes: onboarding seeds data and writes `higgs:meta` and `higgs:data`, then updates React state to render pages.

Local persistence helpers

// app/src/data/repo.js
const DATA_KEY = "higgs:data";
const META_KEY = "higgs:meta";

export function load() {
  const raw = localStorage.getItem(DATA_KEY);
  return raw ? JSON.parse(raw) : null;
}

export function save(data) {
  localStorage.setItem(DATA_KEY, JSON.stringify(data));
}

export function resetAll() {
  localStorage.removeItem(DATA_KEY);
  localStorage.removeItem(META_KEY);
}

Notes: simple Web Storage persistence; reset clears both meta (onboarded flag) and data.

Seed data shape

// app/src/data/seedData.js
export const CATEGORIES = [
  "Housing", "Utilities", "Transportation", "Groceries", "Dining Out",
  "Health & Medical", "Entertainment", "Shopping", "Education",
  "Loan Repayment", "Family & Children", "Gifts & Donations",
  "Travel", "Miscellaneous",
];

export function createSeedData(name = "User") {
  const today = new Date();
  const data = {
    version: 1,
    user: { id: "u1", name, createdAt: today.toISOString().slice(0, 10) },
    categories: CATEGORIES,
    incomes: [],
    expenses: [],
    investments: [],
    loans: [],
    assets: [],
    monthly: {},
    activity: [],
  };
  return recalculateAllStats(data);
}

Notes: seed keeps arrays empty but computes monthly stats to prime the dashboard.

Step-by-Step Learning Activities

Scripted activities to achieve the learning outcomes. Each step includes action, rationale, and self-checks.

1) Prepare environment

  1. Action: Ensure Node 18+ and npm 9+ are installed. Run node -v and npm -v.
  2. Why: Electron + Vite toolchain depends on modern Node features and esbuild.
  3. Check: Versions print without errors.

2) Install dependencies

  1. Action: In the repo root, run cd app && npm install.
  2. Why: Pulls Electron, React, Vite, and build tooling (electron-builder).
  3. Check: node_modules appears; no install errors.

3) Examine data persistence

  1. Action: Open app/src/data/repo.js. Identify load, save, resetAll.
  2. Why: Understand how `localStorage` keys (`higgs:data`, `higgs:meta`) back the app.
  3. Check: Note that onboarding status is stored in `higgs:meta`.

4) Review seed data

  1. Action: Read app/src/data/seedData.js to see categories and the initial data shape.
  2. Why: Seeded data drives the initial dashboard and monthly stats.
  3. Check: Recognize `createSeedData(name)` uses `recalculateAllStats` to populate monthly summaries.

5) Understand the React shell

  1. Action: Open app/src/renderer/src/App.jsx.
  2. Why: This component controls onboarding, sidebar navigation, and which page renders.
  3. Check: Confirm the `page` state drives conditional rendering for Home/Income/Expenses/Investments/Loans/Assets.

6) Run in development

  1. Action: From app, run npm run dev. If prompted, click to open the Electron window.
  2. Why: Experience the hot loaded application via Electron shell and Vite HMR.
  3. Check: Welcome screen renders; no console errors in DevTools.

7) Complete onboarding

  1. Action: Enter a name and click Continue.
  2. Why: Triggers `handleOnboard` → seeds data → writes to `localStorage`.
  3. Check: Home page shows starter stats; storage now has `higgs:data` and `higgs:meta`.

8) Navigate and add entries

  1. Action: Use the sidebar to open Income, Expenses, Investments, Loans, Assets; add at least one record per relevant page.
  2. Why: Exercises the save/recompute flows and UI state updates.
  3. Check: Home totals reflect new entries; refreshing the app preserves data (because of `localStorage`).

9) Reset data

  1. Action: Click Reset in the sidebar and confirm.
  2. Why: Verifies `resetAll` clears storage and returns to onboarding.
  3. Check: Welcome screen reappears; `localStorage` keys are removed.

10) Build distributables

  1. Action: From app, run: 
    npm run build:mac   # macOS
npm run build:win   # Windows
npm run build:linux # Linux
  2. Why: Produces platform installers via electron-builder.
  3. Check: Artifacts appear under app/dist (platform-specific output folders).

Analytical Component (Opinion + Evidence)

Strengths of Electron for Higgs

  • Unified skillset: Web developers can start to ship desktop apps without switching tech stacks.
  • Fast iteration: Vite + Electron gives tight feedback loops, accelerating feature work, and it supports server side updates
  • Cross-platform support: One codebase, three OS targets; electron-builder helps with all the packaging.
  • Local-first: `localStorage` is trivial to wire for a personal finance app with no backend.

Limitations and risks

  • Runtime footprint: Bundled Chromium inflates binary size and memory compared to native or Tauri.
  • Storage durability: `localStorage` is not robust for multi-user, syncing, or large datasets.
  • No Encryption Current version of this application stores everything in LocalStorage as PlainText, you can try encrypting all data for added Security.

Future directions and mitigations

  • Migrate persistence to SQLite (via better-sqlite3) or an dedicated DB for offering data sync and backup.
  • Add secure IPC channels for exporting data, notifications, or OS integration with strict allowlists.
  • Adding realtime investment portfolio net worth with API requests
  • Add automated tests: unit tests for data functions; Playwright for renderer flows; lint and type checks.

Evidence basis: Electron’s ecosystem and docs, Vite’s benchmarked speed.

Future Learning: APIs, Realtime Data, Security

Adding realtime investments with API requests

  • Goal: Replace manual price entry with live quotes. Add a service module (e.g., app/src/data/quotes.js) that fetches from a stock API (Finnhub, Alpha Vantage, or a free sandbox) using fetch in the renderer or via a preload-bridged IPC call for better key hygiene.
  • Pattern: Create a getQuote(ticker) function that returns { price, currency, asOf }. Cache in-memory to reduce calls; throttle requests. Example (renderer-safe fetch):
// quotes.js (renderer)
const API_KEY = import.meta.env.VITE_STOCK_KEY;
export async function getQuote(ticker) {
  const res = await fetch(
    `https://api.example.com/quote?symbol=${ticker}&token=${API_KEY}`
  );
  if (!res.ok) throw new Error("Quote fetch failed");
  const json = await res.json();
  return { price: json.c, currency: json.currency, asOf: json.t };
}
  • UI change: In Investments page, when user types a ticker and quantity, auto-fetch price and show a confirmation. On save, store the fetched price and timestamp for traceability.

Loan auto-deduction from net worth

  • Goal: Track monthly payments and automatically reflect principal reduction in net worth.
  • Approach: Extend the data model: each loan has principal, rate, termMonths, monthlyPayment, nextDueDate, paidHistory.
  • Computation: On app load or when date changes, run a scheduler (e.g., daily check) that applies any due payments: subtract payment from cash, reduce principal by amortized amount, log activity, and recompute stats.
  • UI: Show upcoming due date and a “Run payment now” button; optionally add auto-run toggle.

Data security and encryption

  • Why: LocalStorage is plain text. For better confidentiality, encrypt persisted data.
  • Lightweight option: Use Web Crypto (AES-GCM) in the renderer with a user-supplied passphrase. Store only ciphertext + IV in localStorage; derive a key with PBKDF2/argon2 via Web Crypto.
  • Stronger isolation: Move encryption into preload or a Node module (main process) and expose minimal IPC to encrypt/decrypt blobs. Keep key in memory only; consider prompting per session.
  • Future-proofing: If migrating to a stronger backend (e.g., SQLite), use file-level encryption (SQLCipher) or OS keychain to store secrets.
